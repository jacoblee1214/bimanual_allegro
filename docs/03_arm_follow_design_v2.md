# 3단계 설계안 v2: 손목 자세로 xArm7 EEF 추종

작성 2026-10-19. v1(`03_arm_follow_design.md`)은 M1 의 명세였습니다. v2 는 M1, M2 결과를 반영한 지금의 구조와 실물 첫 시험 계획입니다.

## 1. v1 에서 바뀐 것과 이유

| 바뀐 것 | 이유 (측정) |
|---|---|
| IK 앞에 손목 이상치 차단 (`arm/gate.py`) | 가장자리 영상에서 손목이 한 프레임에 5 cm, 0.5 rad 튐. 좌우 뒤바뀜과 다시 잡힌 손이 원인 (`results/m1_arm_ik.md`) |
| 수렴형 IK → 미분 IK (`arm/ik_v2.py`) | 수렴형은 특이자세 근처에서 해 가지를 건너뛰어, 끝단이 거의 그대로인데 1, 3번 관절이 매 프레임 1 rad 씩 반대로 돎. 미분 IK 는 속도 상한 안에서 한 걸음씩만 가고, 특이자세 근처에서 감쇠를 키움 (`results/m2_diff_ik.md`) |
| 기본 자세 = 시작할 때의 관절값 | 실물 왼팔이 1번 관절 242°, 3번 −243° 처럼 여러 바퀴 감긴 상태. 0° 중심 기본 자세로 당기면 한 바퀴를 풀려고 돎 (사용자 결정, 2026-10-19) |
| 실물 브리지에 다중 안전장치 (`arm/xarm_bridge_node.py`) | 아래 3장 |

## 2. 구조

```
hand_tracker_node ── /<side>/wrist_pose ──▶ arm_follow_node ── arm/joint_states ──▶ xarm_bridge_node ──▶ xArm7
 (비전)                                  gate → clutch 매핑 → DiffIK (100 Hz)           (실물 전용)
                                                  ▲
                                 arm/measured_joint_states (시작 자세)
```

- 시뮬레이션에서는 브리지 대신 `robot_state_publisher` 가 `arm/joint_states` 를 받아 RViz 에 그립니다(`launch/bimanual_sim_v2.launch.py`).
- 손가락 경로는 2단계 그대로입니다.

## 3. 실물 안전장치 (`arm/xarm_bridge_node.py`)

명령이 모터에 닿기까지 차례로 거치는 단계입니다.

1. **`--enable` 이 없으면 아무것도 보내지 않습니다(dry run).** 관절을 읽어 발행하고, 보냈을 명령만 로그에 남깁니다.
2. **명령 끊김:** 0.2 s 동안 명령이 없으면 보내지 않습니다. 서보 모드는 마지막 명령 위치를 유지합니다.
3. **이동 범위:** 모든 관절이 시작 자세 ±`--max-excursion` (기본 0.2 rad) 안에 머뭅니다.
4. **속도:** 한 주기에 `--max-joint-speed × dt` (기본 0.3 rad/s) 까지만 움직입니다. 방향을 유지하도록 모든 관절을 같은 비율로 줄입니다.
5. 컨트롤러 자체의 한계와 충돌 감지는 그대로 켜 둡니다.
6. 오류가 나거나 Ctrl-C 를 누르면 state 4(정지)로 둡니다.

추종 노드(DiffIK)에도 별도로 1.0 rad/s 속도 상한이 있어, 속도 제한이 두 겹입니다.

**dry run 확인 (2026-10-19, 왼팔):** 시작 자세보다 +0.5 rad 를 명령하자 0.2 rad 에서 멈췄습니다. 거기까지 0.3 rad/s 로 66 주기가 걸렸고, 명령이 없을 때는 보내지 않았습니다. 실제로 보낸 명령은 0개입니다.

## 4. 실물 첫 시험 계획 (승인 필요)

한 단계씩 진행하고, 매 단계 전에 사용자 승인을 받습니다. 각 단계에서 사람이 비상정지 버튼 옆에 있어야 합니다.

| 단계 | 내용 | 움직임 |
|---|---|---|
| R0 | 두 팔 상태 읽기, dry run 브리지 + 추종 노드 + 웹캠 (명령 로그만) | 없음 |
| R1 | **왼팔만**, 관절 공간 시험: 1번 관절을 시작 자세에서 +0.05 rad 갔다가 돌아오기. 속도 0.1 rad/s | 1개 관절 3° 정도 |
| R2 | 왼팔, 손목 추종: 이동 범위 0.1 rad, 속도 0.3 rad/s. 작업자는 손을 천천히 수 cm 움직임 | EEF 수 cm |
| R3 | R2 를 범위 0.2 rad 로 | EEF 10 cm 안팎 |
| R4 | 오른팔로 R1~R3 반복 | |
| R5 | 두 팔 동시 | |

시작 전에 확인할 것:
- 왼팔 5번 관절이 6.172 rad 로, 한계(6.28)까지 0.11 rad 만 남아 있습니다. R2 이후에는 관절을 푸는 홈 이동이 필요할 수 있습니다. 홈 이동도 별도 승인을 받습니다.
- URDF 와 실제 컨트롤러의 영점 TCP 가 z 로 20 mm 다릅니다. 상대 이동이라 R1~R3 에는 영향이 작지만, 원인은 확인할 것입니다.
- 손(Allegro)은 R1~R3 동안 연결하지 않습니다. 팔만 먼저 봅니다.

## 5. 남은 일

- 손목 방향 추종을 끌지 여부. 교차 영상에서 방향 오차 p95 가 1.4 rad 입니다. 처음에는 위치만 따르고 방향은 고정하는 모드를 두는 것도 방법입니다.
- 미분 IK 의 이득이 주기 단위라서 30 Hz 평가값과 100 Hz 노드의 거동이 다릅니다. 실물 전에 100 Hz 기준으로 다시 맞춥니다.
- 손 장착 변환, 두 팔 사이 거리 실측.
