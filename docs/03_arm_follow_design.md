# 3단계 설계안: 손목 자세로 xArm7 EEF 추종

작성 2026-10-19. 한 팔 먼저, 시뮬레이션 먼저 진행합니다.

## 1. 범위

- 입력: 비전 노드의 `/<side>/wrist_pose` (PoseStamped, `camera_optical` 프레임)
- 출력: xArm7 관절 목표 7개. 시뮬레이션에서는 RViz, 실물에서는 xArm SDK 로 보냅니다.
- 이번 마일스톤(M1)은 녹화 영상에서 나온 손목 궤적으로 IK 를 오프라인으로 돌려, 도달 가능성과 관절 속도를 측정하는 데까지입니다.

## 2. 상대 이동 (clutch)

카메라 한 대로 잰 손목 절대 위치는 거리 오차가 큽니다. 손 크기 추정이 10% 틀리면 거리도 10% 틀립니다(01 문서 3.3). 그래서 절대 위치 대신, 클러치를 건 순간부터의 변화량만 로봇에 옮깁니다.

클러치를 건 순간의 손목 자세를 `(p_W0, R_W0)`, EEF 자세를 `(p_E0, R_E0)` 라 하면 이후 목표는 다음과 같습니다.

```
p_E = p_E0 + s · R_cb · (p_W − p_W0)
R_E = (R_cb · R_W · R_W0ᵀ · R_cbᵀ) · R_E0
```

- `R_cb`: 카메라 프레임 → 로봇 base 프레임 회전입니다. 기본값은 "작업자가 카메라를 마주 보고, 로봇은 작업자와 같은 쪽을 본다"는 가정입니다. 작업자가 카메라 쪽으로 손을 내밀면 로봇은 앞(+x)으로, 작업자의 왼쪽(영상 오른쪽, 카메라 +x)은 로봇 왼쪽(+y)으로, 위(카메라 −y)는 로봇 위(+z)로 갑니다.
  ```
  R_cb = [[0, 0, -1],
          [1, 0,  0],
          [0, -1, 0]]
  ```
- `s`: 이동 배율이고 기본값은 1.0 입니다.
- 회전 변화량은 카메라 프레임에서 구해 base 프레임으로 옮긴 뒤 EEF 의 시작 방향에 곱합니다.

## 3. IK

- 모델: `xarm_description` (xarm_ros2 jazzy) 에서 xacro 로 만든 xArm7 URDF, 끝 프레임은 `link_eef` 입니다.
- 풀이: pinocchio 로 감쇠 최소제곱(damped least squares)을 쓰고, 위치와 방향 오차 6차원을 다룹니다. 이전 해에서 출발합니다(warm start).
- 남는 자유도 1개: 영공간(null space)에서 기본 자세 쪽으로 당겨 팔꿈치가 떠돌지 않게 합니다.
- 제한: URDF 관절 한계, 한 주기당 관절 변화량 상한(관절 속도 제한), 작업공간 상자로 목표 위치를 자릅니다.
- 도달 실패 시: 해가 수렴하지 않으면 그 프레임은 목표를 버리고 이전 관절값을 유지합니다. 그렇게 버린 프레임 수를 셉니다.

## 4. 측정 (M1)

입력은 `data/clips/v2_*.avi` 에서 비전 노드 로직으로 뽑은 손목 궤적입니다. 카메라 보정이 아직 없어서 근사 K(fx = fy = 600, 640x480 중심)를 씁니다. 보정 후 다시 측정해야 하는 값입니다.

| 항목 | 정의 |
|---|---|
| 도달률 | IK 가 위치 1 mm, 방향 0.01 rad 안으로 수렴한 프레임 비율 |
| 추종 오차 | 목표 EEF 와 실제 FK 의 위치·방향 차이 (중앙값, p95) |
| 관절 속도 | 프레임 간 관절 변화량 / dt 의 최대값과 p95, xArm7 한계와 비교 |
| 관절 한계 접근 | 한계 0.1 rad 안에 들어간 프레임 비율 |
| 계산 시간 | 프레임당 IK 시간 (중앙값, p95) |

## 5. 정해지지 않은 것

- 두 팔의 실제 장착 위치와 방향(양팔 base 사이 거리, 바라보는 방향). 시뮬레이션은 `config/arms_sim.yaml` 의 임시값을 씁니다.
- 손 장착 방향(xArm 플랜지 → Allegro base_link 변환). 시뮬레이션은 임시값입니다.
- 실물 제어 방식: xArm SDK 의 서보 모드(`set_servo_angle_j`)와 위치 모드 중 무엇을 쓸지는 실물 단계에서 정합니다.
