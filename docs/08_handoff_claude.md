먼저 읽을 것: 이 문서 → `AGENTS.md` → `README.md` → `docs/03_arm_follow_design_v2.md` 4장 → `docs/results/r5_*.md`, `r6_*.md`, `m7_*.md`

## 1. 목표와 단계

사용자는 Hyunsu Lee 입니다. 사람이 작업하는 영상을 보고 로봇이 같은 작업을 하게 만드는 것이 최종 목표입니다. 로봇은 xArm7 두 대와 Allegro Hand V6 좌우 한 쌍입니다.

1. 비전: 두 손 추적, 좌우 구분, 손목 위치 — 완료
2. 양손 텔레옵 (시뮬레이션) — 완료
3. 팔 EEF 추종 — 실물 양팔까지 완료 (R5), 깊이 보정 개선 중 (R6, R7)
4. 실물 팔과 실물 손 결합, 데이터 기록 — 아직
5. VLM — 아직. 사용자가 원하는 것은 **영상을 이해한 결과로 팔과 손을 동시에 제어하는 것**입니다. LLM/VLM 호출은 실시간 루프에 넣기에 느리므로, 영상 이해 층과 4단계 데이터로 학습한 정책(VLA) 층을 어떻게 잇는지가 설계의 핵심입니다.

Claude 의 역할은 개발 도우미이면서 비전 알고리즘을 직접 만드는 담당입니다. 모델은 Opus 를 씁니다.

## 2. 작업 규칙 (사용자가 정한 것)

- **실물을 움직이는 명령은 매번 먼저 묻습니다.** xArm, Allegro 모두 해당합니다. 상태 읽기는 묻지 않아도 됩니다.
  - 자동 모드 분류기가 `--enable` 실행을 막으므로, 실물 구동은 사용자가 터미널에서 직접 실행합니다. Claude 는 명령을 정확히 적어 주고, 끝나면 로그를 분석합니다.
- **마일스톤마다 묻지 않고 commit 과 push 를 합니다.** 이 저장소에만 해당합니다.
- **기존 스크립트나 문서를 고칠 때는 새 버전 파일**(`foo_v2.py`)을 만들고 옛 파일은 둡니다. README 는 한 파일로 두고 최신을 가리키게 고칩니다.
- **설치는 목록을 먼저 보여 준 뒤** 진행합니다. sudo 는 사용자가 `! <명령>` 으로 실행합니다.
- **공개 저장소**이므로 연구실 IP, 시리얼 번호, 회사 로고, 내부 문서는 커밋하지 않습니다. IP 는 `config/robots.local.yaml`(git 무시)에만 둡니다.
- `~/v6f_manuse_teleoperation`(원익 드라이버)은 고치지 않습니다. `~/V6_Teleoperation` 은 읽기 전용입니다.
- 프로세스는 자기가 띄운 것만 PID 로 끕니다. 이름으로 `pkill` 하지 않습니다.
- 로봇 그래프는 `ROS_DOMAIN_ID=42` 입니다. Claude 의 시험과 서브에이전트는 **77** 을 씁니다.
- **사용자가 실행할 스크립트는 저장소 안에 둡니다.** `/tmp` 의 scratchpad 는 재부팅 때 지워집니다(11월 6일 재부팅으로 R5~R7 스크립트가 사라졌습니다).
- 답변은 한국어로 하고, 근거 없는 낙관 없이 측정값으로 말합니다.

## 6. 알려진 문제

- 종료할 때 `KeyboardInterrupt`, `process has died` 가 찍힙니다. ROS 노드의 종료 방식 때문이며 동작에는 영향이 없습니다.
- 비대화형 bash 에서 `&` 로 띄운 프로세스는 SIGINT 를 무시합니다. 끌 때는 PID 에 SIGTERM 을 보냅니다.
- 팔 venv 에서 cv2/numpy 문제로 테스트 3개를 `--ignore` 하고 있습니다(기존 문제).
- 왼손 PnP 는 손바닥 기울기 해가 두 개 사이에서 뒤집힙니다. 깊이 보정(fusion v2 이상)으로 해결했습니다.
- fusion v3 의 약점: 깊이 공백 동안 앞뒤로 움직이면 공백이 끝날 때 한 번에 튑니다(`m7_hold_v3.md`).
- README 의 앞부분 일부가 옛 상태를 설명합니다.
