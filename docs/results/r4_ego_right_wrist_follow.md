# R4: 오른팔이 에고 RealSense 로 본 작업자 오른손을 따라가기

- 날짜: 2026-10-19
- 실행과 분석: Claude Opus 5.5 (총괄). 사용자 승인 후 진행했고, 사용자가 로봇을 지켜봤습니다.
- 설정: 왼팔 R3 와 같습니다(`r3_ego_left_wrist_follow.md`). `--side right`, 시작 직전 IMU 측정에서 아래로 44.3° 였습니다.

## 결과

| 항목 | 왼팔 R3 | 오른팔 R4 |
|---|---|---|
| 손 검출 | 552/898 | 790/900 |
| 이상치 차단 (거부 / 재클러치) | 0 / 2 | 76 / 4 |
| 축별 상관 (앞 / 왼쪽 / 위) | 0.85 / 0.87 / 0.87 | **0.44 / 0.85 / 0.60** |
| 범위 (손 × 0.5 → 팔 끝, mm) | 77→73 / 69→41 / 134→117 | 133→91 / 76→51 / 149→109 |
| 팔 끝 최대 이동 | 70 mm | 70 mm |
| 관절 최대 변화 / 속도 | 0.192 rad / 0.311 rad/s | 0.279 rad / 0.320 rad/s |
| 범위 밖 명령 | 0 | 0 |
| 종료 | 32 s 스스로 정지, 오류 0 | 32 s 스스로 정지, 오류 0 |

추종 노드가 종료할 때 `publisher's context is invalid` 오류를 한 번 냈습니다. SIGINT 로 rclpy 가 먼저 닫힌 뒤 타이머가 한 번 더 발행하려 한 것으로, 브리지가 이미 멈춘 뒤라 동작에는 영향이 없습니다.

## 손목 추정 흔들림

| | 프레임간 이동 p50 / p95 (mm) | 축별 p95 앞 / 왼쪽 / 위 (mm) | 카메라 깊이 범위 |
|---|---|---|---|
| 왼손 (R3) | 3.6 / 16.2 | 9.1 / 4.1 / 11.8 | 268 mm |
| 오른손 (R4) | 6.9 / **60.5** | **42.0** / 8.6 / **43.4** | 347 mm |

흔들림은 카메라 깊이 방향에 몰려 있습니다. 카메라가 44° 기울어 있어서 깊이 오차가 로봇의 앞과 위 축에 섞이고, 좌우 축은 거의 흔들리지 않습니다. 단안 PnP 의 깊이가 MediaPipe 손 크기 추정에 비례하는 문제입니다. 손등에서 이 배율이 흔들린다는 것은 `m2_scale_jitter.md` 에서 확인했습니다. 이번에 오른손이 왼손보다 훨씬 나빴던 이유(손 방향, 화면 위치)는 따로 나눠 보지 않았습니다.

## 다음

손목 깊이를 RealSense 깊이로 직접 재면 이 축의 흔들림을 근본적으로 줄일 수 있습니다. 지금은 USB 2 연결이라 컬러와 깊이를 함께 받지 못합니다(`05_ego_camera.md` 4장). 그래서 USB 3 케이블이 다음 단계의 핵심입니다. 그 전까지의 대안은 깊이 방향 필터 강화, 손등일 때 배율 고정, 배율 축소입니다.
