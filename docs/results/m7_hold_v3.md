## 요약

- **문제**: v2 의 `hold` 는 PnP 손목 × 최근 30 개 비율(센서 거리 / PnP 거리)의 중앙값입니다. 깊이가 끊기기 직전에 PnP 거리가 잠깐 틀리면 이 중앙값이 오염되고, 공백 내내 손목이 멀리 놓였다가 깊이가 돌아올 때 튑니다(R6 직전 dry run 에서 123 mm, R6 에서 `hold → depth` 최대 149 mm, `r6_ego_depth_follow.md`).
- **고른 방법 (`v3`)**: 마지막 센서 손목의 카메라로부터의 거리(광선 방향 거리)를 기억해 두고, 지금 프레임의 랜드마크 0 화소 광선 위 그 거리에 손목을 놓습니다. 옆 방향은 영상을 계속 따라가고, 거리는 센서가 마지막으로 본 값에 머뭅니다. PnP 의 거리는 전혀 쓰지 않습니다.
- 제안받은 두 가지 보강, 즉 (1) 공백 동안 PnP 의 상대 거리 변화(지금 / 마지막 센서 프레임)로 거리를 고치는 것과 (2) 최대 유지 시간 뒤 PnP × 비율로 넘어가는 것은 **넣지 않았습니다**. (1) 을 그대로 하면 오염이 없어도 `v3` 보다 나빴고, PnP 거리를 중앙값으로 다듬고 변화의 절반만 쓴 형태는 오염이 없을 때 오른손 1~2 s 공백에서 더 좋았지만 오염에서는 크게 나빴습니다. (2) 는 2 s 공백에서 `v3` 보다 나빴습니다(4.3).
- 오염 재현(공백 직전 0.6 s 동안 PnP 거리 × 0.65): v2 가 붙드는 비율이 참값의 **1.44 배**(왼손 p50) / 1.40 배(오른손)가 됐습니다. dry run 의 1.02 / 0.65 ≈ 1.57 과 같은 현상입니다. 1 s 공백에서 공백 중 위치 오차 p50 / p95 가 왼손 v2 157.7 / 300.9 mm → v3 **10.2 / 87.8 mm**, 공백 끝 계단은 153.5 / 325.5 → **27.6 / 121.3 mm** 입니다. v3 는 오염이 있든 없든 거의 같은 값을 냅니다(4.1).
- 오염이 없을 때도 필터 전 공백 중 오차는 모든 경우에 v3 가 작습니다(왼손 1 s p50 38.4 → 10.2 mm). 공백 끝 계단은 짧은 공백에서 v3 가 작지만, 손을 앞뒤로 움직이는 `depth` 단계의 2 s 공백에서는 v3 가 **더 큽니다**(p50 왼 68.6 → 90.1, 오른 46.9 → 97.1 mm). 공백 동안의 앞뒤 움직임을 v3 는 따라가지 않고, 깊이가 돌아올 때 한 번에 반영하기 때문입니다(5장).
- 영상 속 자연 공백(오프라인, 마스크 없음): `hold → depth` 계단이 왼손 4 번 p50 43.1 / 최대 89.0 → 15.7 / 31.5 mm, 오른손 1 번 217.7 → 17.5 mm 입니다.
- `vision/hand_tracker_node_v5.py --fusion v3` 가 녹화 영상에서 29.9 fps 로 발행했고, 오프라인 추적기와 위치(최대 차이 0.0 mm), 출처, `pixels` 가 프레임마다 같았습니다. `/<side>/wrist_depth_diag` 의 `pixels` 가 이제 채워집니다(`depth` 프레임 100%).

## 1. 만든 파일

| 파일 | 역할 |
|---|---|
| `vision/depth_wrist_v3.py` | `WristDepthV3`(v2 와 같은 호출 방식), `FusedWristV3(FusedWristV2)`(`pixels` 필드 추가). NumPy 만 써서 `.venv-arm` 에서도 import 됩니다 |
| `tools/eval_depth_wrist_v3.py` | 공백 모의 실험, `data/results/m7_hold_v3.json` 작성. OpenCV 없이 돌아갑니다 |
| `tests/test_depth_wrist_v3.py` | 합성 깊이 영상 시험 6개. 5개는 NumPy 만, 1개(`hand_tracker_ego_v3` 에 끼워 보기)는 OpenCV 가 없으면 건너뜁니다 |
| `vision/hand_tracker_node_v5.py` | 노드 v4 + `--fusion v3`. 노드 클래스와 시간 기록은 v4 에서 import 하고, `main()` 만 v4 를 복사해 선택지를 더했습니다(v4 의 `main()` 이 파서와 융합 선택을 안에서 만들어 그대로 쓸 수 없음) |
| `tools/eval_node_v5_ros.py` | 노드 v5 를 ROS 로 끝까지 돌려 확인, `data/results/m7_node_v5_ros.json` 작성. 주제 목록과 비율 요약은 `tools/eval_node_v4_ros.py` 에서 import |

`hand_tracker_ego` 의 새 버전은 만들지 않았습니다. `WristDepthV3` 가 `fusion_factory` 규약(`__call__`, `reset`)을 그대로 따르고, 추적기의 σ 규칙(`depth` 만 5 mm, 나머지 45 mm)도 그대로 맞기 때문입니다.

`WristDepthV3.__call__(pose, image_landmarks, world_landmarks, depth_m, camera_matrix, side) -> FusedWristV3`:

| 출처 | 조건 | 위치 | `rotation` | `scale` |
|---|---|---|---|---|
| `depth` | 센서 평면이 있고 비율이 절대 범위(0.5~2.0) 안 | v2 와 같음(랜드마크 0 광선 × 센서 손바닥 평면) | 센서 손바닥 좌표계 | 센서 / PnP 비율 |
| `hold` | 그 밖, 앞서 `depth` 프레임이 있었음 | 지금 랜드마크 0 화소 광선 위, 마지막 `depth` 손목의 카메라 거리 | `None`(호출자가 PnP 회전 사용) | 놓인 손목 거리 / PnP 거리 |
| `pnp` | 첫 `depth` 전, 또는 `reset()` 뒤 | PnP 그대로 | `None` | 1.0 |

- `measured` 는 v2 와 같이 이번 프레임의 비율(범위 검사 전), `pixels` 는 `palm_depth` 가 남긴 화소 수(센서 값이 없으면 `None`)입니다. 범위 밖이거나 평면이 시선에 너무 비스듬해 `hold` 가 된 프레임에도 `pixels` 가 있을 수 있습니다.
- `hold` 프레임에 깊이 영상이 아예 없어도(`depth_m=None`) 화소 광선을 만들 수 있도록, 마지막 깊이 영상의 크기를 기억합니다.
- 추적기는 한쪽 손이 0.3 s 넘게 안 보이면 `reset()` 을 부르므로, 손이 화면 밖으로 나갔다 들어오면 다음 `depth` 프레임까지 `pnp`(배율 1.0)입니다. v2 와 같습니다.

## 2. 문제 다시 보기

v2 의 `hold` 비율은 분모가 PnP 거리입니다. M6(`m6_wrist_flip.md` 3.4)에서 본 것처럼 그 분모가 흔들리는 쪽입니다. 이 영상에서도 오염을 넣지 않은 공백의 첫 프레임에서 v2 가 붙든 비율 / 참 비율이 p50 1.00, p95 1.26 / 1.20, 최대 1.54 / 1.48(왼 / 오른, 1 s)이었습니다. 중앙값은 맞아도 그 순간 PnP 가 틀려 있으면 손목이 그만큼 어긋납니다. 오염을 넣으면 p50 이 1.44 / 1.40 으로 올라갑니다.

비율을 어떻게 고르든 PnP × 비율은 공백 동안 PnP 의 거리 오차를 그대로 받습니다. 그래서 v3 는 공백 동안 거리를 PnP 에서 가져오지 않습니다.

## 3. 평가 방법

`ego_depth_424` 는 v2 가 프레임의 97.6%(왼) / 98.1%(오른)에서 센서를 써서 자연 공백이 거의 없습니다. 그래서 공백을 흉내 냈습니다.

| 항목 | 내용 |
|---|---|
| 공백 | 길이 0.3 / 1 / 2 s 구간 안의 모든 검출에 `depth_m=None`. 구간 시작을 3 s 부터 0.2 s 간격으로 옮김 |
| 유효한 공백 | 구간 바로 앞 프레임과 바로 뒤 프레임이 기준에서 `depth` 이고 연속(0.05 s 미만 간격)인 것만. 자연 공백과 겹치는 것을 뺌 |
| 경우 | `clean`: 어디서나 / `depth 단계`: 녹화의 `depth` 단계(손을 카메라 쪽으로 앞뒤로 움직임) 안에 완전히 들어간 구간 / `오염`: `clean` 에 더해 구간 직전 0.6 s 동안 PnP 위치 × 0.65 |
| 기준 | 같은 프레임을 공백 없이 돌린 v2 (센서 손목) |
| 공백 중 오차 | 공백 프레임 가운데 기준이 `depth` 인 프레임의 \|변형 − 기준\|, 모든 공백을 모아 p50 / p95 / max |
| 끝 계단 | 공백 뒤 첫 프레임 − 공백 마지막 프레임, 공백마다 하나. 실제 손 움직임도 들어 있으므로 기준 자체의 계단을 같이 적음 |
| RayKalmanV2 | `vision/depth_filter_v2.RayKalmanV2` 기본값, `depth` 프레임 σ_ray 5 mm, 그 밖 45 mm (라이브 `hand_tracker_ego_v3` 와 같음). 필터 거친 변형과 필터 거친 기준을 공백과 그 뒤 0.5 s 동안 비교, 계단은 공백 마지막 프레임부터 0.5 s 뒤까지 가장 큰 프레임 간 이동 |
| 실행 | 각 공백마다 구간 3 s 앞부터 0.5 s 뒤까지 융합 객체를 새로 만들어 돌림(v2 의 30 개 창은 1 s) |

센서 평면(`WristDepthV3.measure` 의 결과)은 검출마다 한 번만 `depth.npy` 에서 계산해 두고 다시 썼습니다. 융합 클래스 자체는 바꾸지 않고 `measure` 만 저장값을 돌려주게 했습니다. 실제 깊이 영상으로 돌린 `WristDepthV3` 와 위치, 출처가 완전히 같은 것을 개발 중에 확인했습니다(오른손 400 검출, 1.5 s 공백 포함, 최대 차이 0.0. 이 확인은 JSON 에 없습니다).

## 5. 약점

1. **공백 동안의 앞뒤 움직임을 따라가지 않습니다.** 거리를 마지막 센서 값에 묶어 두므로, 공백 동안 손이 카메라 쪽으로 다가가거나 멀어진 만큼이 깊이가 돌아오는 순간 한 번에 들어옵니다. `depth 단계 2s` 의 끝 계단 p50 이 v2 보다 큽니다(왼 68.6 → 90.1, 오른 46.9 → 97.1 mm). p95 와 max 는 v3 가 작습니다(왼 188.7 → 129.4, 오른 177.3 → 135.4 mm). 이 동안 로봇은 앞뒤로 움직이지 않습니다.
2. **실제 공백의 주된 원인(손이 0.163 m 보다 가까움)은 이 영상에 없습니다.** 영상의 센서 손목 거리는 p5~p95 가 왼손 0.304~0.463 m, 오른손 0.287~0.447 m 이고, 공백은 모두 흉내 낸 것입니다. 최소 거리 때문에 깊이가 끊기면 실제 손은 유지 거리보다 가까이 있으므로 v3 는 손을 조금 멀리 둡니다. 다만 그 차이는 손이 최소 거리보다 얼마나 더 다가갔는지까지로 묶이고, v2 의 오염처럼 30% 를 넘게 벗어나지는 않을 것으로 봅니다 **[의견: 측정 안 함]**.
3. **공백 직전 마지막 센서 프레임 하나에 기댑니다.** 그 프레임이 틀렸으면(평면이 소매나 손가락에 걸렸는데 절대 범위 안) 공백 내내 그 값이 유지됩니다. v2 의 중앙값은 이런 한 프레임 오류에 강했습니다. 이번 영상에서는 문제가 보이지 않았지만 따로 시험하지 않았습니다.
4. **필터가 끝 계단을 줄이지 못합니다**(4.2). 팔 쪽의 0.5 배, 반경, 속도 상한이 마지막 방어입니다. 필요하면 `hold` 뒤 처음 몇 `depth` 프레임의 σ_ray 를 키우는 방법이 있지만 시험하지 않았습니다.
5. 손이 0.3 s 넘게 안 보였다 돌아오면 `reset()` 때문에 첫 `depth` 프레임까지 PnP 그대로(배율 1.0)입니다. R6 의 비율 0.66 이면 그 몇 프레임 동안 손목이 약 1.5 배 멀리 놓입니다. v2 와 같은 동작이고 이번에 바꾸지 않았습니다.

## 6. 한계

- 작업자 한 명, 영상 하나(`ego_depth_424`, 약 33 s)입니다. 공백과 PnP 오염은 모두 흉내 낸 것이고, 오염은 단순한 곱셈(× 0.65, 0.6 s)입니다. 손이 카메라에 아주 가까울 때(손이 화면을 크게 차지할 때) PnP 와 MediaPipe 가 어떻게 틀리는지는 이 영상에 없습니다.
- 기준은 v2 의 센서 손목이지 정답이 아닙니다. 센서 평면 자체의 잡음과 틀린 프레임이 오차에 섞여 있습니다(짧은 공백에서도 max 가 50~100 mm 인 것은 일부 이 때문으로 봅니다 **[의견]**).
- 실물 로봇과 실시간 카메라로는 시험하지 않았습니다. 노드는 녹화 영상 재생으로만 확인했습니다.
- `WristDepthV3` 호출 시간은 따로 재지 않았습니다. `depth` 프레임의 계산은 v2 와 같고(`m6_wrist_flip.md` 4장, 손 하나 p95 약 0.58 ms), `hold` 프레임은 광선 하나만 계산합니다.
