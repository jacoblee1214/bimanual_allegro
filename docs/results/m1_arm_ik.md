# M1 결과: xArm7 IK 와 상대 이동, 녹화 손목 궤적으로 오프라인 평가

- 날짜: 2026-10-19
- 구현: Gemini 4 Argon (High), `agy` CLI. 명세는 `docs/03_arm_follow_design.md` 입니다.
- 검증과 분석: Claude Opus 5.5 (총괄)
- 입력: `data/trajectories/v2_{palm,palm2,back,cross}.npz`. `tools/extract_wrist_trajectories.py --gpu` 로 뽑았고, 근사 K(fx = 600) 와 One Euro 초기값을 썼습니다.
- 원자료: `data/results/m1_arm_ik.json`

```bash
~/allegro_vision_teleop/.venv/bin/python tools/extract_wrist_trajectories.py data/clips/v2_*.avi --gpu
.venv-arm/bin/python tools/eval_arm_ik.py
.venv-arm/bin/python -m pytest -q tests/test_arm_ik.py tests/test_arm_follow.py
```

## 1. 만든 것

| 파일 | 내용 |
|---|---|
| `arm/ik.py` | `ArmIK`: pinocchio 감쇠 최소제곱 6D IK. 이전 해에서 출발하고, 관절 한계로 자르고, 영공간에서 기본 자세 쪽으로 당깁니다 |
| `arm/follow.py` | `RelativeFollower` (설계 2장 식 그대로), `R_CB`, 관절 속도 제한 `limit_step` |
| `tools/eval_arm_ik.py` | 설계 4장 측정 항목과 배율별 도달률 |
| `tests/test_arm_ik.py`, `tests/test_arm_follow.py` | IK 왕복 수렴, 관절 한계, 축 방향, 회전 변화량, 배율, 작업공간 자르기 |

기본 자세 `q_rest = [0, -0.3, 0, 0.7, 0, 1.0, 0]` rad 에서 EEF 는 base 앞 0.37 m, 위 0.35 m 에 있고 도구 z 축은 아래를 봅니다. 관절 한계에서 가장 가까운 것도 0.89 rad 떨어져 있습니다.

## 2. 검증 (총괄)

- **재현:** 평가를 다시 돌려 Argon 이 보고한 표와 같은 값이 나왔습니다.
- **테스트:** 팔 환경에서 11개 모두 통과합니다. 비전 환경에서는 56개가 통과하고, pinocchio 가 필요한 3개는 건너뜁니다.
- **뮤테이션 확인:** `R_CB` 의 부호 하나를 뒤집으면 따라가기 테스트 3개가, 회전 곱셈 순서를 바꾸면 1개가 실패합니다.
- **고친 것:** Argon 의 테스트는 모듈 수준에서 `pytest.importorskip` 을 썼습니다. ROS 의 launch_testing pytest 플러그인 때문에 이 방식은 비전 환경에서 **전체 실행을 건너뛰게** 만들었습니다(0개 수집). 마커로 건너뛰는 방식으로 바꾸고, 같은 실수가 반복되지 않도록 `AGENTS.md` 에 적었습니다. `arm/follow.py` 는 numpy 만 쓰므로 그 테스트는 두 환경에서 모두 돕니다.

- 관절 속도 한계는 URDF 값인 3.14 rad/s 를 썼습니다.
- 위치와 방향 오차는 속도 제한을 거친 **명령**과 목표 사이의 차이입니다. 그래서 속도 제한에 많이 걸리면 오차가 커집니다.

- 배율 2.0 에서도 도달률은 91~100% 였습니다.

## 4. 해석

**IK 는 병목이 아닙니다.** 모든 프레임에서 수렴했고, 한 번 푸는 데 0.1 ms 도 걸리지 않습니다.

**문제는 비전 쪽 손목 자세가 튀는 것입니다.** 궤적 자체의 프레임 사이 변화량을 따로 재 보았습니다(Claude 분석).

| 궤적 | 손 | 회전 속도 p95/최대 rad/s | 0.5 rad 넘게 튄 프레임 | 직선 속도 p95/최대 m/s |
|---|---|---|---|---|
| palm (가장자리까지) | 왼 | 26.7 / 38.5 | 33 | 2.65 / 4.87 |
| palm (가장자리까지) | 오른 | 18.0 / 49.6 | 21 | 1.83 / 3.96 |
| palm2, back (안쪽) | 양손 | 1.1~2.3 / 2.9~4.0 | 0 | 0.39~0.79 / 0.76~2.50 |
| cross | 양손 | 2.7~2.8 / 15.9~23.0 | 2 | 0.67~0.78 / 1.14~1.42 |

- 사람 손목이 1/30 초 사이에 0.5 rad 넘게 돌거나 5 m/s 로 움직이지는 않습니다. 이것은 측정 오류입니다.
- `palm` 은 일부러 손을 영상 가장자리까지 움직인 영상으로, V2 에서 라벨이 31% 틀린 영상입니다.
- 이 영상에서 튐(위치 5 cm 초과 또는 회전 0.5 rad 초과)은 손마다 44건이었습니다. 그중 다른 손의 직전 위치에 더 가깝게 떨어진 경우가 왼손 14건, 오른손 7건으로 좌우 뒤바뀜입니다. 놓친 프레임 직후에 생긴 경우는 10건, 22건으로 다시 잡힌 손입니다. 두 분류는 겹칠 수 있습니다.
- 운용 조건(두 손이 가로 가운데 60% 안)을 지킨 `palm2`, `back` 에서는 튐이 없습니다. 이때 관절 속도 요구는 p95 기준 한계 안이고, 최대값만 한계의 1.2~3.9배였습니다.

## 5. 다음 단계에 반영할 것

1. **IK 앞단에 손목 이상치 차단을 넣습니다.** 한 프레임에 위치가 수 cm, 방향이 0.5 rad 넘게 바뀌면 그 프레임은 버립니다. 손을 놓쳤다가 다시 잡으면 클러치를 다시 겁니다. 조사 문서(`docs/04_rnd_candidates_survey.md`)의 0순위 후보와 같은 결론이고, 이번 데이터가 근거를 더해 줍니다.
2. **좌우 유지를 추적 ID 로 합니다.** 조사 문서의 2순위 후보입니다. 가장자리 영상의 튐 상당수가 좌우 뒤바뀜이었습니다.
3. **실물 속도 제한은 URDF 값보다 훨씬 낮게 시작합니다.** 안쪽 영상에서도 순간 요구가 12 rad/s 까지 나왔습니다. 첫 실물 시험은 0.5 rad/s 수준에서 시작하기를 권합니다.
4. 근사 K 와 One Euro 초기값으로 잰 결과입니다. 카메라를 보정한 뒤 같은 명령으로 다시 측정합니다.

## 6. 하지 못한 것

- 실제 xArm7 의 관절별 속도와 가속 한계는 확인하지 않았습니다. URDF 값만 썼습니다.
- 두 팔을 함께 둔 작업공간과 충돌은 보지 않았습니다(두 base 사이 1.5 m, 측정 전).
- 손 장착 변환(플랜지에서 Allegro base_link)이 없어서, EEF 는 xArm 의 `link_eef` 입니다.
