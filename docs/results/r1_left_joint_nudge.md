# R1 결과: 왼팔 1번 관절 +0.05 rad 왕복 (첫 실물 시험)

- 날짜: 2026-10-19
- 실행과 분석: Claude Opus 5.5 (총괄). 사용자 승인 후 진행했고, 사용자가 실제 움직임을 눈으로 확인했습니다.
- 계획: `docs/03_arm_follow_design_v2.md` 4장 R1

```bash
.venv-arm/bin/python arm/xarm_bridge_node_v2.py --side left --enable --max-joint-speed 0.1 --max-excursion 0.06 --ros-args -r __ns:=/left
.venv-arm/bin/python tools/nudge_joint.py --joint 1 --delta 0.05 --ros-args -r __ns:=/left
```

## 2. 첫 실행에서 찾아 고친 것 (브리지 v1 → v2)

- **목표값을 엔코더로 착각:** SDK `get_servo_angle()` 의 기본값 `is_real=False` 는 컨트롤러 목표값을 돌려줍니다. 첫 실행 기록은 그래서 완벽한 계단 모양이었습니다. v2 는 엔코더(`is_real=True`)와 목표값을 따로 발행합니다.
- **종료 처리:** v1 은 Ctrl-C 때 rclpy 오류 메시지를 내며 끝났습니다. `finally` 의 정지는 실행됐습니다. v2 는 SIGINT 와 SIGTERM 을 직접 받습니다. 백그라운드로 띄운 프로세스는 SIGINT 를 무시 상태로 물려받기 때문에, 직접 설치하지 않으면 정지 신호가 듣지 않았습니다.
- **범위 상자:** R2 dry run 에서 관절마다 따로 자르자 관절 5개가 상자 끝에 붙었고, 팔 끝이 의도하지 않은 곳으로 향했습니다. v2 는 상자를 벗어나는 명령을 통째로 무시하고 그 자리에 멈춥니다.

## 3. 같이 확인한 것

- **기구학:** URDF 순기구학에 컨트롤러의 툴 오프셋(z 80 mm)을 더하면, 컨트롤러가 보고하는 TCP 와 3~4 mm 차이입니다(두 팔). 앞서 본 "영점에서 20 mm 차이"는 팔이 비활성일 때 읽은 값이었습니다.
- **두 팔 모두 어깨 특이자세 근처에 있습니다.** 2번 관절이 왼팔 7°, 오른팔 −7° 로 0 에 가깝고, 1번과 3번이 서로 반대로 감겨 있습니다(왼팔 +242°/−243°). 자코비안 최소 특이값은 0.035~0.036 으로, 시뮬레이션 기본 자세의 0.209 보다 훨씬 작습니다. R2 dry run 에서 팔 끝 3~9 cm 이동에 관절이 0.5 rad 씩 움직이려 한 원인입니다. **R2 전에 홈 이동이 필요합니다.**
