# 실물 팔 + 실물 손 텔레옵: 검토와 단계별 실행 (2026-11-26)

- 작성: Claude (Fable 5.2). 실물은 움직이지 않고 검토했습니다. 측정값은 녹화 영상 `data/clips/ego_depth_work` 를 도메인 77 에서 재생한 것과, 두 손을 읽기 전용으로 점검한 것입니다.
- 목적: 에고 카메라가 본 조작자의 두 손을 xArm7 두 대(손목)와 Allegro Hand V6 두 개(손가락)가 동시에 따라가게 하는 것입니다. 팔은 R5 에서 실물로 확인했고, 손은 한 손씩만 실물로 확인된 상태였습니다(`allegro_vision_teleop/docs/HANDOVER.md` 5장).

## 1. 만든 것

| 파일 | 역할 |
|---|---|
| `launch/teleop_real.launch.py` | `demo_v2.launch.py` 에서 팔(`arms:=sim\|dry\|true`)과 손(`hands:=mock\|left\|right\|both`)을 따로 고르게 한 것 |
| `tools/run_teleop_real.sh` | 점검(카메라 USB 3, 기울기 측정, 팔 자세, 손 통신) → 확인 질문 → 실행 → 기록 → 요약 |
| `hand/hand_bridge_node.py` | 손 저장소의 브리지에 관절 속도 제한(3 rad/s)과 "측정값에서 시작"을 더한 것 |
| `tools/record_run_v2.py`, `tools/analyze_run.py` | 손 명령과 손 측정값까지 기록하고 요약 |
| `config/teleop_real.yaml` | 홈 자세, 팔과 손의 제한값 |
| `tools/run_real_ego_v3.sh` | 팔만 도는 R7 스크립트. 카메라가 손을 못 보면 팔 노드를 띄우지 않고, 홈 자세에서도 시작 |

손의 주소는 `config/robots.local.yaml` 의 `allegro:` 에 있습니다(git 무시).

## 2. 실행 순서

한 단계가 괜찮을 때만 다음으로 갑니다. 태그는 매번 새 이름을 씁니다.

```bash
cd ~/bimanual_allegro
tools/run_teleop_real.sh t1                              # 1. 팔 dry run, 손 가상: 아무것도 안 움직임
tools/run_teleop_real.sh t2 --hands right                # 2. 실물 오른손만 (팔은 dry run)
tools/run_teleop_real.sh t3 --hands both                 # 3. 실물 두 손
tools/run_teleop_real.sh t4 --arms real                  # 4. 실물 두 팔 (손 가상) = R7
tools/run_teleop_real.sh t5 --arms real --hands both     # 5. 전부
```

- 시작하면 30 초 안에 두 손이 카메라에 보여야 합니다. 아니면 멈춥니다.
- 60 초 뒤 자동으로 멈춥니다(`--duration`). Ctrl-C 는 언제든 전체를 멈춥니다.
- 카메라 기울기는 실행마다 IMU 로 다시 재서 `data/runs/<tag>/ego_camera.yaml` 에 두고 그 값을 씁니다. `config/ego_camera.yaml`(30.2°)은 건드리지 않습니다.
- 손은 카메라에서 0.35~0.6 m 에 둡니다. 끝나면 나오는 요약의 `wrist z` 로 확인합니다.

## 3. 검토 결과: 알고리즘과 실제 동작이 맞는가

### 3.1 맞는 것 (측정으로 확인)

- **전체 경로가 끝까지 돕니다.** 녹화 영상 40 초 재생: 손목 25~28 Hz, 팔 명령 100 Hz, 손 명령 100 Hz, 손 관절 한계 밖 명령 0 건, 종료 후 남은 프로세스 0.
- **홈 자세에서 시작해도 팔 추종이 됩니다.** `check_pose_v2` 는 홈 자세를 "not ready"(joint2 12°)로 판정하지만, 7 cm 구의 26 방향 모의 실험에서 sigma 최소 0.136 / 0.129(좌 / 우)로 READY 오른팔(0.116)보다 높았습니다. 재생에서도 EEF 이동 최대 65 / 70 mm(제한 70), 관절 속도 0.30 rad/s(제한 0.3)였습니다.
- **카메라 방향 변환**은 추종 노드가 `R_CB` 로 하며, 이 행렬은 IMU 측정에서 나옵니다. 카메라를 옮겨도 실행 스크립트가 다시 재므로 맞습니다. 단, 카메라가 조작자와 같은 쪽을 볼 때만 맞습니다(마주 보면 앞뒤, 좌우가 뒤집힘).

### 3.2 고친 것

- **손 명령이 순간적으로 35~42 rad/s 까지 튀었습니다.** 추적이 손을 놓쳤다 다시 잡을 때 목표가 뛰고, 기존 브리지의 EMA(0.25)가 그 1/4 을 한 틱(10 ms)에 내보냅니다. `hand/hand_bridge_node.py` 로 3 rad/s 로 제한했습니다. 같은 재생에서 p99 3.2 rad/s 가 되었습니다(기록 시각 오차로 최대값은 3.6, 6.0 으로 찍힘). 보통의 손가락 움직임(p95 3.6 rad/s)도 조금 깎이므로, 실물에서 괜찮으면 `config/teleop_real.yaml` 에서 올립니다.
- **dry7b 는 카메라 없이 40 초를 돌았습니다.** 지금은 손목 자세가 안 오면 멈춥니다.

### 3.3 실물에서만 확인되는 것 (아직 모름)

1. **손 드라이버가 켜질 때 손가락이 펴집니다.** 드라이버 소스(`v6_hardware_interface.cpp` 의 `on_activate`)가 위치 명령을 초기 위치 표로 채우고 매 주기 보냅니다. 표의 값을 따로 주는 곳은 찾지 못했으므로 0(편 손)으로 봅니다. 지금 두 손은 MCP 가 77~85° 굽은 채 쉬고 있어서(2026-11-26 읽음), 브링업 순간 약 80° 움직입니다. 토크 제한은 0.1 Nm 입니다. 소스에서 읽은 것이고 이 구성에서 본 것은 아닙니다. **2 단계에서 손 주변을 비우고 확인합니다.**
2. **실물 두 손을 동시에 돌린 적이 없습니다.** 네임스페이스 분리는 가상 손으로만 확인했습니다.
3. **에고 시점에서 실물 왼손의 손가락 방향.** 왼손은 벌림 관절 부호가 공식 URDF 와 다릅니다(손 저장소 HANDOVER 4.2). 정면 웹캠 + 왼손 실물은 확인됐고, 에고 시점(`--no-undo-mirror`)은 RViz 로만 확인했습니다. 3 단계에서 엄지와 벌림 방향을 봅니다.
4. **손을 단 팔의 하중 설정.** 팔 제어기에 손 무게가 설정돼 있는지 읽지 않았습니다. R5 가 손을 단 채로 통과했다면 문제없을 가능성이 큽니다.
5. **종료할 때 손.** 드라이버가 내려가면 연결을 닫습니다. 그때 손가락 힘이 빠지는지 유지되는지는 보지 못했습니다.

### 3.4 알고 쓰는 제한

- 팔은 위치만 따라갑니다(`--position-only`). 손목을 돌려도 로봇 손의 방향은 시작 자세 그대로입니다.
- 홈 자세에서는 앞으로 뻗는 방향이 약 5 cm 에서 멈춥니다(관절 범위 제한). joint4 가 범위 끝(16.0°)에 닿는 것이 재생에서도 보였습니다.
- 손이 화면에서 사라지면 팔은 그 자리에서 멈추고(0.2 s 뒤), 손가락은 마지막 모양을 유지합니다.
- RViz 의 손 장착 방향은 임시값(항등)입니다. 표시만 다르고 제어에는 쓰이지 않습니다.
- 재생한 영상은 손이 카메라에서 0.28 m(중간값)로 가까워서, 손목 거리의 25~29% 가 PnP 대체값이었습니다. 실물에서는 0.35 m 이상을 지킵니다.
